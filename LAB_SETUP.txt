Standalone collection and ACT evaluation on the lab PC

Only prox_learning_real is needed. The parent prox_learning checkout and sibling
ACT checkout are not imported by collection or evaluation. Simulation and the old
parent-repository conversion/viewer commands are optional separate workflows.

Included layout
  record_act_waypoints.py      automated A -> B collection
  record_dataset.py           shared logging, cameras and sensors
  cameras.py, sensor_layout.py camera and proximity capture
  kinesthetic.py              shared FR3 limits and impedance gains
  act_model/                  local checkpoint-compatible ACT architecture
  models/act_test_20/          policy_best.ckpt, dataset_stats.npz,
                              training_config.json, image_metadata.json, manifest.json
  eval_act_real.py             offline inference and real-robot evaluation
  eval_pc_act_real.py          paired PC-ACT evaluation with live proximity history
  models/pc_act_test_20/        policy/encoder pair, statistics, image settings,
                              checksum binding and background guard profile
  submodules/franky/           source for the local Franky tracker build

Transfer
  A ready archive is at dist/prox_learning_real_lab.tar.gz after running:
    python make_lab_bundle.py
  Copy the archive to the lab PC and extract it:
    tar -xzf prox_learning_real_lab.tar.gz
    cd prox_learning_real
  It includes the ACT weights and Franky source. It excludes recordings, analysis
  artifacts, Git metadata, credentials/config folders, installed binaries and caches.
  Hardware/Python dependencies must be installed on the target PC.

  Alternatively transfer this whole directory, or commit/push these changes and clone
  prox_learning_real on the lab PC. When using Git, the .ckpt file uses Git LFS:
    git lfs install
    git submodule update --init --recursive
    git lfs pull
  The deployment archive already contains the real checkpoint, not an LFS pointer.
  Generated recordings and analysis output are not necessary for a real rollout.

Python dependencies
  Use Python 3.10 or 3.11 in the environment where the working Franky build is installed.
  Collection only:
    python -m pip install -r requirements-collection.txt
  Collection plus ACT evaluation:
    python -m pip install -r requirements-eval.txt
  These include the Torch 2.7.1 / torchvision 0.22.1 pair used to verify deployment.
  The portable NPZ normalization statistics do not require NumPy-2 pickle support.
  No training package, dataset registration, ImageNet download or W&B account is required.

  Keep your working Franky installation if it exposes JointImpedanceTracker.
  Otherwise build the included source, after configuring the lab PC's robot-compatible
  libfranka, Eigen3 (>=3.4), ruckig (0.17.3), CMake/compiler and pybind11 dependencies:
    python -m pip install --no-build-isolation ./submodules/franky
  Use this source rather than assuming an arbitrary PyPI Franky build has the custom
  streaming tracker API. Existing real-time OS permissions/FCI setup still apply.

Checks (no robot or camera connections)
    python check_lab_setup.py
    python eval_act_real.py --check-model --device cpu
  Without hardware drivers installed yet:
    python check_lab_setup.py --offline-only
  The model check loads the local checkpoint and produces a finite (50, 8) action chunk
  from dummy RGB/state input. It does not reset or move the robot.

Collection
    python record_act_waypoints.py --episodes 20 --seed 0 \
      --wrist-serial 836612071883 --exo-serial 943222071556 \
      --output recordings/new_batch
  Use the serials for the physical training views. All paths remain under this folder
  when commands are run from its root. There are no gripper commands.

Real evaluation
    python eval_act_real.py \
      --wrist-serial 836612071883 --exo-serial 943222071556 \
      --output eval_rollouts/trial_01
  This resets to training pose A before running the policy. Training A/B and motion
  assumptions still apply. See README.md for limits, asynchronous inference and logs.
  --ckpt-dir selects a different local deployment bundle.

Offline check against a recording (optional; requires copying that recording)
    python eval_act_real.py --offline-row recordings/act_test_20/episode_0000 \
      --device cpu --output eval_rollouts/offline_ep0

Exporting a newly trained model
  Run in the training environment, where the legacy pickle can be read:
    python export_act_model.py --source /path/to/training/checkpoint_directory \
      --data-dir /path/to/converted_training_dataset \
      --destination models/my_new_model
  Copy the resulting model folder to the lab PC. All inference metadata is inside it.
  The exporter requires saved training_config.json or W&B training config.yaml.
  --image-height / --image-width can supply image dimensions instead of --data-dir.

PC-ACT obstacle probe
  The included PC-ACT pair is scratch-trained epoch 1825. Its sensitivity to sensor
  changes is very small; do not rely on it to avoid the obstacle. See README.md's
  real PC-ACT section for the experimental guard and limitations.
    python eval_pc_act_real.py --check-model --device cpu
  Remove the obstacle before resetting to A:
    python eval_pc_act_real.py --reset-only
  Place a soft, fixed test object with stopping clearance, out of both camera views.
  First check the incoming sensors without moving the arm:
    python eval_pc_act_real.py --sensor-check --duration 20
  The real rollout requires the arm already at A and does not reset by default:
    python eval_pc_act_real.py \
      --wrist-serial 836612071883 --exo-serial 943222071556 \
      --output eval_rollouts/pc_act_obstacle_live_01
  --proximity-mode clear supplies all-clear policy inputs for a matched comparison;
  actual sensors are still logged and still feed the independent guard. A guard
  abort is logged separately and must not be described as learned avoidance.
  Copy the entire models/pc_act_test_20 folder, not just policy_best.ckpt.
